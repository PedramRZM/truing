# react-patterns: how React 19 and Next.js 16 code looks

This skill shows the usual React 19 and Next.js 16 rules as before/after code. All examples come from one neutral storefront app (products, categories, collections, a cart, price alerts) with English copy. Read only the module you need:

| Module                                     | Read when                                                                                                                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `references/state-and-effects.md`          | adding `useState`, `useEffect`, `useReducer`; a value "must stay in sync"; an `exhaustive-deps`, `set-state-in-effect` or purity rule fires; loading/error flags multiply                                                 |
| `references/composition-and-boundaries.md` | deciding where `'use client'` goes; passing server-rendered UI into an interactive wrapper; creating a context; a component takes a fifth boolean prop; an icon-only button                                               |
| `references/data-and-actions.md`           | a page or component needs data; a form submits; a list should update before the server answers; cached data must refresh after a change; an error needs a retry                                                           |
| `references/ui-craft.md`                   | a skeleton or loading state; a spinner or pending state; an optimistic toggle, its rollback, or undo; tooltips on icon buttons; a shared-element or page transition; motion started from script or gated on a weak device |

## Project rules come first

The project's own rules (CLAUDE.md, AGENTS.md, lint config, design-system docs, decision records) outrank this skill. If an example here disagrees with them, follow the project. File paths and names, class names, design tokens, formatting (semicolons, quote style, import grouping) and the storefront domain are all illustrative: take the pattern, not the names. If a pattern here and a lint rule disagree, the lint rule wins and the example is wrong for that project.

## Check the project's switches first

Some advice depends on how the project is set up. Look at `package.json` and `next.config.*` before copying code.

| Switch           | Where to look                                                                  | Effect on the examples                                                                                                                                                                                                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React Compiler   | `reactCompiler: true` in `next.config.*` (needs `babel-plugin-react-compiler`) | On: no `useMemo`, `useCallback` or `memo` by default; add one only with a measured reason, and leave existing ones in place, because removing them can change the compiler's output (react.dev). Off: write plain code and memoise only with a measured reason.                                                                  |
| Cache Components | `cacheComponents: true` in `next.config.*`                                     | On: `'use cache'`, `cacheLife`, `cacheTag` and `updateTag` apply; `params` is passed down under `<Suspense>`; Next.js keeps a few previous routes mounted but hidden (`<Activity>`). Off: the previous caching model (`fetch` cache options, `unstable_cache`, `revalidateTag`, `revalidatePath`); routes unmount on navigation. |
| React version    | `react` in `package.json`                                                      | 19.2 or newer: `useEffectEvent` and `<Activity>`. `<ViewTransition>` needs React 19.3 or the canary React the Next.js App Router bundles; the `react` package from npm does not export it in 19.2 (checked on 19.2.7).                                                                                                           |
| Next.js version  | `next` in `package.json`                                                       | 16.2: error boundaries use `unstable_retry` and `unstable_catchError`, the route config is `unstable_instant`, view transitions need `experimental.viewTransition`. 16.3 and later: `retry`, `catchError` and `instant`, no view-transition flag.                                                                                |
| Zod version      | `zod` in `package.json`                                                        | The schema code in the examples runs on Zod 3 and Zod 4; use the syntax your major version documents for anything beyond it.                                                                                                                                                                                                     |
| Tailwind version | `tailwindcss` in `package.json`                                                | The CSS in `ui-craft.md` is Tailwind v4 syntax (`@utility`, `group-has-data-pending:`).                                                                                                                                                                                                                                          |

Anything the modules mark "(Next.js 16.3+)" is absent from the Next.js 16.2.9 bundled docs. To check an API against the installed version, grep `node_modules/next/dist/docs/` for its name; if it is not there, it is newer than the installed Next.js.

## Status of the examples

The examples were adapted from a set that had been linted and type-checked in the app it came from. Moving them into this storefront domain, and rewriting some of them for Next.js 16.2, React 19.2 and Zod 3, means the adapted code has not been linted in your project. When they were adapted, the snippets were also compiled once against React 19.2.7, Next.js 16.2.9 types and TypeScript 5.5, with stand-ins for the app's own imports, and linted once with `eslint-plugin-react-hooks` 7.1 (its `recommended` set, which includes the React Compiler rules): the "after" code was clean, and the "before" code in sections 1, 2 and 4 of `state-and-effects.md` raised `set-state-in-effect` and `exhaustive-deps`. That checks syntax, prop names and the hooks rules, not behaviour or the project's other lint rules. Re-check an example against the project's lint and types when you use it. The measurements in `references/ui-craft.md` were taken in the original app (Next.js 16.3, React 19.3); treat them as expected behaviour, and measure again in your project.

## Precedence

The project's rules come first, then this skill, then any other React skill installed on the machine. In particular, Vercel's `react-best-practices` skill (if present in `~/.claude/skills`) predates React 19.2's `useEffectEvent` and still recommends latest-ref and handler-ref patterns and manual memoisation. Where the project enables the React Compiler, do not add `useMemo`, `useCallback` or `memo` without a measured reason.
