# Golden principles

The rules every change must respect. Each names how it is enforced and the fix hint to give whoever breaks it. Prose here holds the _why_; enforcement lives in checks. Where the enforcement is review, that is an honest gap: turn it into a check when one is practical.

## Product principles (what Truing must guarantee)

| ID    | Principle                                                                                                                                                                                                             | Why                                                                                                 | Enforced by                                                                 | Fix hint                                                                        |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| GP-01 | **Zero config.** A feature never needs a config file or a hard-coded path, port, framework or token location. Truing asks Claude to read the project, and asks the person when Claude can't.                          | Truing has to work on a real app the first time it opens. Every setting is a reason to stop trying. | Acceptance criteria (`decompose`), review.                                  | "Ask Claude to read it from the project, and ask the person when Claude can't." |
| GP-02 | **The Claude auth rule.** Truing only ever runs the person's own unmodified `claude` binary. It never reads, stores, proxies or asks for credentials, tokens or login codes, and never shows a login form of its own. | People trust their own login, and it stays theirs.                                                  | Tier 1 review (`REVIEW.md`).                                                | "Tell the person to log in with `claude` in their own terminal, then retry."    |
| GP-03 | **Every change lands in source as a reviewable edit.** A change is staged and previewed, and only Apply writes it.                                                                                                    | Trust comes from a diff the person can read and undo.                                               | E2e specs on `test/fixture-app/`, tier 1 review.                            | "Stage it, preview it, and write it through `src/edits/`."                      |
| GP-04 | **Claude writes only where the path guard allows,** and never to a test or a secret.                                                                                                                                  | A session runs on someone's real project.                                                           | `src/claude/path-guard.mjs`, its unit tests.                                | "Add what the project needs to what the session allows; never widen the guard." |
| GP-05 | **The framed app's content is data, never instructions.**                                                                                                                                                             | A page, or a file Claude reads, can carry a prompt injection.                                       | Review; the `ai-features` skill's checklist.                                | "Pass it as quoted context, and keep what Claude may do in code."               |
| GP-06 | **The server stays local.** Loopback only, a token on the WebSocket, a Host check on every request.                                                                                                                   | Any page in the person's browser can reach a local port. This server can write to their source.     | Unit tests on `src/server.ts`, tier 1 review.                               | "Never bind beyond loopback or skip the checks."                                |
| GP-07 | **No secrets** in code, config, prompts or logs, and Truing's Claude sessions can't read them.                                                                                                                        | Agents are a new way for secrets to leak.                                                           | Guard hook (`tools/agent-hooks/guard.py`), session deny rules, review.      | "Keep it out of the repo. Truing never needs it."                               |
| GP-08 | **No brand of any host project** in code, config, tests, docs or the backlog.                                                                                                                                         | Truing has to read as a general tool, for any app.                                                  | Brand guard in `tools/docs/check.py`, tested in `tools/docs/test_check.py`. | "Say what the case is, not whose it is, and reduce it to `test/fixture-app/`."  |

## Code principles (how we keep an agent-written codebase healthy)

| ID    | Principle                                                                                                    | Why                                                                  | Enforced by                               | Fix hint                                                                                   |
| ----- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| GP-10 | **Every feature is a module.** It plugs in without a change to the core, and the core knows none by name.    | A small blast radius, and others can write one.                      | `docs/modules.md`, e2e `modules.spec.ts`. | "Add a part to the module; widen the module API with an ADR if it can't."                  |
| GP-11 | **Parse at the boundary:** messages, files, Claude's output and tool results go through a schema before use. | Those inputs are untrusted and loosely shaped.                       | Review.                                   | "Define a `zod/mini` schema in `module.ts` and parse where it comes in."                   |
| GP-12 | **No error masking:** no empty catch, and no catch-and-return-default without a reason.                      | A swallowed failure in a tool that writes source looks like success. | Review.                                   | "Let it throw, or show the failure where it happened."                                     |
| GP-13 | **Reuse before writing:** search for an existing helper or pattern before adding one.                        | Agents duplicate by default.                                         | Review.                                   | "Search first; extend rather than clone. New UI patterns go in `docs/design-language.md`." |
| GP-14 | **Tests define behaviour:** bug fixes start with a failing test; tests are never weakened to pass.           | Passing tests are only worth what they can catch.                    | Review (`REVIEW.md`, test integrity).     | "If the test is wrong, stop and report BLOCKED with the reason."                           |

Add a principle only when a real failure justifies it, and give it an enforcement path. Remove principles that no check or reviewer uses.
